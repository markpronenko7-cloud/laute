# Кабинеты партнёров LAUTE

## Компактное ТЗ

- Администратор входит прежним паролем в `/admin`. Раздел «Кабинеты» управляет менеджерами, клиентами и заказами. Старый доступ CMS не меняется.
- Менеджер входит по личному логину через `/account`, меняет временный пароль, работает только со своими клиентами и заказами. Доступ к CMS и управлению сотрудниками ему не выдаётся.
- Клиент входит через `/account`, обязательно меняет временный пароль, видит свои цены, контакт менеджера и историю. Изменять скидки и статусы он не может.
- Карточка: название, форма организации, двухбуквенный код страны ISO, налоговый номер, контактное лицо, email, телефон. Регистрационные и банковские реквизиты необязательны и соответствуют стране. ИНН РФ проверяется по длине 10/12 цифр, БИН/ИИН Казахстана — 12 цифр. Проверка существования организации и контрольных сумм в объём не входят. Адрес магазина не собирается.
- Администратор задаёт менеджеру предел скидки 0–99%. Менеджер назначает скидки клиенту по категориям/брендам в пределах лимита. Повторяющиеся правила запрещены. Уменьшить лимит ниже действующих скидок нельзя.
- Пересечение скидок **не считается согласованным бизнес-правилом**. По умолчанию сочетание правил бренда и категории запрещено. Для их совместного назначения менеджер явно выбирает бренд, категорию или большую скидку. Суммирование не предусмотрено.
- Временный пароль генерирует сервер. Он показывается один раз, доступы копирует и передаёт менеджер. Сброс отзывает все сессии клиента. Отключение кабинета блокирует вход и отзывает сессии. Отключение менеджера останавливает новые заказы его клиентов до переназначения.
- Заказ: товар → количество → проверенная сервером сумма → подтверждение суммы → сохранение заказа в очереди менеджера. Разные валюты считаются отдельно, конвертации нет. Товары без цены или скрытые товары отправить нельзя.
- Статусы: отправлен → получен менеджером → в работе → отгружен → завершён; отмена доступна до отгрузки. «Получен» назначает сотрудник, сохранение заказа само по себе не означает, что менеджер его прочёл.
- История хранит цены и суммы на дату заказа. Повтор заказа заменяет корзину после подтверждения и пересчитывает цены. При недоступном товаре повтор останавливается с его артикулом.
- Заказ сохраняется в Supabase и доступен менеджеру в кабинете/админке. Автоматические email/мессенджер-уведомления для этих заказов не заявлены. Существующие публичные заявки продолжают работать отдельно.

## Защита и ограничения

RLS и отсутствие публичных прав на таблицы. RPC проверяет серверную сессию, роль и владельца каждого действия. Пароли — bcrypt/pgcrypto (как действующая Supabase-аутентификация CMS); это не scrypt. Пять неверных попыток блокируют аккаунт на 15 минут. Сессия — 8 часов, токен только в sessionStorage, в базе хранится SHA-256 токена. Изменение пароля отзывает другие сессии. Пароль от 12 символов, до 72 байт.

Цена пересчитывается сервером; перед отправкой проверяется хеш расчёта и ревизия скидок. Повтор запроса с тем же UUID возвращает исходный заказ. Изменения карточки защищены от перезаписи устаревшей версии. Складские остатки информационные: резервирования, оплаты, счетов и интеграции с бухгалтерией в этом этапе нет.

## Развёртывание и проверки

1. Выполнить `supabase/migrations/20261019_partner_portal.sql` в SQL Editor проекта LAUTE. Миграция создаёт новые приватные таблицы и функции одной транзакцией, существующие CMS-таблицы не изменяет. Выполняется один раз.
2. `npm ci`, `npm run test:admin`, `npm run build`.
3. Изолированные проверки PostgreSQL без рабочих данных: `npm install --prefix .temp/qa --no-save --no-audit --no-fund @electric-sql/pglite@0.5.10`, затем `npm run test:partners`. Временная тестовая зависимость не попадает в сайт.
4. Публикация — push в `main`, GitHub Actions → Pages. Проверить `/laute/account`, старый `/laute/admin`, создание менеджера и клиента, первый вход, индивидуальные цены, отправку, получение и повтор заказа.

`src/ai/` не изменяется. Техническая документация не заменяет проверку применения миграции и опубликованного пути.

## Приёмочные проверки 19 октября 2026

- 15 существующих регрессионных проверок CMS и 60 проверок новой PostgreSQL-миграции прошли; production-сборка Vite успешна.
- В браузере на изолированном стенде: вход клиента, скидка 20%, три единицы товара, сумма 69 360 ₽, сохранение заказа, его получение менеджером, отображение подтверждения клиенту и повтор в корзину с новым расчётом. Создание международного клиента AE и выдача временных доступов также проверены. Проверен экран шириной 390 px.
- Миграция применена в рабочем Supabase. Там же одной отменяемой транзакцией проверены кабинеты, смена временных паролей, персональная цена реального товара, отправка и повтор запроса заказа, подтверждение менеджером, границы ролей, RLS и отзыв сессий. Тестовые аккаунты и заказы отменены через `ROLLBACK`.
- Внешние HTTP-проверки рабочего Supabase: запрос кабинетов без сессии отклонён; неверный логин отклонён; прямое чтение всех трёх приватных таблиц запрещено.
- Реальные кабинеты сотрудников и клиентов создаются администратором после ввода их реквизитов; фиктивные учётные записи в продакшне не оставлены.
